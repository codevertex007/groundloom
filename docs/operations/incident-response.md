# Incident response

Classify security/privacy, data integrity/loss, availability, quality/model, cost abuse, and dependency incidents. First protect users/data: disable affected tool/worker/feature/model profile, revoke credentials/URLs, stop deletion/publication/export if unsafe, and preserve evidence.

Establish commander, timeline, scope/workspaces/versions, communication, mitigation, recovery, and validation. Avoid broad tenant-content access; use IDs/metadata/redacted traces and approved break-glass with audit. Follow up with root cause, missed detection, tests/dataset/runbook/docs/ADR changes, owner, and due dates.
